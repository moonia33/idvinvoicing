### Projektas
- Projektas yra apskaitos sistema, kuri skirta infividualią veiklą vykdantiems asmenims.
- Sistema leidžia išrašyti sąskaitas faktūras, gauti mokėjimus ir valdyti finansines operacijas.
- Sistema taip pat leidžia valdyti išlaidas, pajamas ir finansines operacijas.
- Sistema yra modulinė, prireikus plečiama per modulius, pavyzdžiui: darbuotojų valdymas, atsargų valdymas, finansų valdymas.
- Sistema yra parašyta Python programavimo kalba.
- Sistema naudoja PostgreSQL duomenų bazę.
- Sistema naudoja Django framework.
- Sistema naudoja django ninja api
- FE parašytas svelte sveltekit naujausia vesrija
- FE naudoja shadcn ui
- FE maksimaliai optimizuotas greičio ir saugumo aspektais
- FE naudoja tailwindcss
- FE maksimaliai intuityvus ir suprantamas
- FE naudoja TypeScript
- FE maksimaliai patogus, kiek įmanoma supaprastintas
- Pradinis projektas ne PVM mokėtojams
- Projekto būtina sąlyga - mokesčių apskaičiavimas ir ataskaitos, įskaitant eksportą nustatytu formatu excell
- Nustatymai, kurie susiję su pardavėju(individualią veiklą vykdančiu asmeniu) suvedami pačiame projekte, ne env
- Projektas turi būti dokerizuotas, kad būtų galima lengvai paleisti ir naudoti naujam asmeniui arba kad izoliuotai galėtų dirbti keli asmenys naudojant vieną BE (reikia tikslintis ir patarimo iš agentų)
- Būtina naudoti geriausias praktikas
- Būtina naudoti git
- GIT repo: https://github.com/moonia33/idvinvoicing.git
- pirkimai gali būti pln valiuta, bet konvertuojami į EUR. konvertavimas nurodomas ranka, keičiasi kiekvieno mokėjimo metu
- SMTP ir sąskaitų siuntimas yra būtinas
- Recuring invoicing ir auto siuntimas būtinas
- Reikalingas sprendimas, kai vienas asmuo vykdo kelias veiklas, kurių apskaita atskirta


### Tech stack
- **BE**: Python 3.13, Django 5.2, django-ninja (REST API + OpenAPI), PostgreSQL 16, WeasyPrint (PDF), openpyxl (Excel), django-q2 (foninės užduotys, ORM broker), uv (paketų tvarkymas), pytest + pytest-django, ruff, mypy
- **FE**: SvelteKit 3 / Svelte 5, TypeScript, shadcn-svelte (preset nova/neutral, lucide, Inter), Tailwind CSS v4, adapter-node, openapi-typescript (tipai iš BE OpenAPI), pnpm, vitest + playwright
- **Infra**: Docker + docker-compose (postgres, backend, qcluster, frontend, caddy reverse proxy), GitHub Actions CI, Coolify-compatible deploy

### Architektūros sprendimai (patvirtinta)
- **Multi-tenant**: bendra DB schema, kiekviena verslo eilutė turi `tenant_id` FK; filtravimas per middleware. Self-host = 1 tenant, bendras BE = N tenant'ų. Be django-tenants (schema-per-tenant) – per sudėtinga; izoliacijai sustiprinti vėliau galima Postgres RLS.
- **Auth**: session cookies (httpOnly + CSRF), vartotojas+slaptažodis, viskas už vieno Caddy reverse proxy. JWT tik jei prireiks mobilios app.
- **Pinigai**: DecimalField(12,2), EUR; niekada float.
- **Sąskaitos**: serija + nuoseklus numeris per tenant (unikalus); statusai draft → issued → (partially_paid) → paid | cancelled; PDF per WeasyPrint server-side.
- **Mokesčiai**: `TaxRule` lentelė su `year` lauku (tarifai keičiasi kasmet → fixtures per metus); variklis skaičiuoja GPM, VSD, PSD; leidžiamų atskaitymų metodai – abu (30% fiksuoti IR faktinės), sistema parodo kas palankiau.
- **Apskaitos principas**: per-tenant `accounting_basis` – `cash` (pinigų principas: pajamos pagal mokėjimo datą) arba `accrual` (kaupimo principas: pajamos pagal sąskaitos išrašymo datą); taikoma pajamoms IR išlaidoms, skaičiuojant žurnalą ir mokesčių bazę.
- **Ataskaitos**: pajamų-išlaidų žurnalas + mokestinė suvestinė → Excel (openpyxl). i.SAF nereikalinga (ne PVM).
- **FE/BE sutartis**: ninja OpenAPI schema → openapi-typescript → tipizuotas FE klientas. API versijuojama: `/api/v1/`.
- **Nustatymai**: SellerProfile modelis per tenant (rekvizitai, serijos, atskaitymų metodas) – DB, ne env.
- **Kelių veiklų palaikymas**: veikla = atskiras tenant; `User` ↔ N tenant'ų per `TenantMembership` (role); FE tenant switcher; visa apskaita (sąskaitos, žurnalas, mokesčiai, numeracija) izoliuota per tenant.
- **El. paštas**: `mailer` app – per-tenant SMTP settings DB (slaptažodis šifruojamas `cryptography` Fernet iš SECRET_KEY), `EmailOutbox` modelis (status, retry); siuntimas per qcluster.
- **Recurring sąskaitos**: `RecurringInvoiceTemplate` (klientas, eilutės, dažnumas, next_run_date, auto_send) → qcluster dieninis job generuoja sąskaitą ir, jei auto_send, deda į outbox su PDF.
- **Valiutos**: pirkimas/išlaida turi `currency` (EUR|PLN), `amount_original`, `exchange_rate` (rankinis, kaskart skirtingas) → `amount_eur`; visa apskaita/ataskaitos – EUR.
- **Deploy**: Caddy = vidinis routeris (vienintelis public servisas); Coolify – eksponuojamas tik `caddy` servisas, Traefik→Caddy. Tas pats compose tinka grynam VPS ir Coolify.
- **SvelteKit 3 ypatumai**: adapter konfigūruojamas `vite.config.ts` `sveltekit()` opcijose (nėra `svelte.config.js`); lib alias – `#lib` (ne `$lib`); `layout.css` – `src/routes/`; `LayoutProps` tipai.

### Struktūra
```
backend/
  config/                  # Django settings
  apps/
    tenancy/               # tenant, user, seller profile
    invoicing/             # klientai, sąskaitos, eilutės, mokėjimai, PDF
    ledger/                # pajamų-išlaidų žurnalas, kategorijos
    taxes/                 # mokesčių taisyklės, skaičiavimo variklis
    reports/               # Excel eksportas
    mailer/                # per-tenant SMTP, EmailOutbox, siuntimo taskai
    core/                  # shared: money, numbering, audit
frontend/                  # SvelteKit app
deploy/                    # Caddyfile, compose
docker-compose.yml         # prod-like
docker-compose.dev.yml
.github/workflows/         # CI
```
